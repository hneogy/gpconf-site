# Decisions (gpconf-site)

Append-only. Corrections are new entries. Numbered S-001… to keep them apart from the corpus's D-numbers.

**S-001 — Static site, Python build, no framework.** Seven pages of mostly prose with two reading levels each, plus small client-side tools and charts, do not need a JavaScript framework. The build is one Python script (`build.py`, Jinja2 templates, ~150 lines) producing plain HTML into `dist/`; the scheduled jobs are Python too, so the repository has one language. Jinja2 is the only dependency and is pinned in `requirements.txt`. Considered and rejected: Eleventy or Astro (a Node toolchain for template inheritance alone), hand-written HTML (seven pages × shared header, footer and toggle would drift), committing `dist/` (generated noise; Cloudflare Pages builds it).

**S-002 — Hosting: Cloudflare Pages Git integration, Python build.** Cloudflare's current (v3) Pages build image ships Python 3.13 and pip and honours `.python-version`; the build command is `pip install -r requirements.txt && python build.py`, output directory `dist`. Every commit, including the jobs' data commits, triggers a rebuild, which is how the pages get fresh values without client-side fetching. To be confirmed when the project is connected; the fallback is a GitHub Actions deploy with `wrangler pages deploy`, which needs an API token the owner would create.

**S-003 — Pages are rendered from the jobs' JSON at build time.** The home, tracker and library pages carry their numbers in the HTML, so they work without JavaScript and search engines see them. JavaScript adds only the history charts (fetching `/data/tracker/history.json` from the same origin) and the two tools. Nothing on any page contacts anything but this origin; the CSP (`default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; form-action 'none'`) enforces it. No external fonts, images or scripts, so the Zenodo DOI badge is a text link.

**S-004 — Reading level is a client-side toggle over duplicated content, default Simple.** Each page contains both versions in `.lvl-simple` and `.lvl-technical` blocks; a pre-paint script applies the stored choice (`localStorage`, key `gpconf-level`) or `?level=` and defaults to Simple; with scripts off both versions show with labels. Rejected: two URL trees (double the pages to link and index; the toggle would be a navigation) and server-side variants (the choice must persist across pages instantly).

**S-005 — Fetch budget and rotation.** Five daily endpoints (the last-30-days CSV and TLE, the analyst CSV and TLE, the Starlink SupGP CSV) plus stable-source drift checks. The corpus has 22 stable CelesTrak sources; re-fetching all of them one day a week would be 27 requests that day, over the owner's ~10/day. Instead each source is due 6.5 days after its last check and the job takes at most 4 due sources per run, oldest first, so every source is checked about weekly and no run exceeds 9 requests. The fetcher refuses a repeated URL and enforces a hard cap of 10 before sending anything; no redirects, no retries, 2 s between requests, a User-Agent naming the project and site; tested in `tests/test_tracker.py`. One expected 404 a day (the last-30-days TLE) is far under CelesTrak's 50-errors-per-2-hours threshold.

**S-006 — Derived measurements only, by construction.** The tracker computes record counts, the highest id, six- and nine-digit counts, the HTTP status of the TLE request, count relations, and per-source SHA-256 comparisons; the outputs never contain a field other than `NORAD_CAT_ID`-derived integers, statuses, byte counts, hashes and timestamps. Raw bodies stay in memory in CI; a local `--cache-dir` (git-ignored) exists for inspection. A test asserts that no element value from the test input appears in any output. The library job stores verdicts, versions and exception text only.

**S-007 — Worked examples.** The only element sets on the site are (a) the CCSDS 502.0-B-3 annex G OMM example (GOES 9) as printed in the standard and as rendered into a TLE by the corpus renderer (checksums verified), used for the side-by-side, the anatomy tool, the highlighted provider-convention columns and the library reproducers; and (b) the corpus's published derived Alpha-5 line for catalog 100000 (SARAMAGO, first record), whose provenance sidecar is public. No CelesTrak element set is displayed otherwise, no SupGP value anywhere, nothing from Space-Track. The provider rendering differences are shown as highlighted columns on the annex G line, conventions only.

**S-008 — Seed history.** The tracker history starts with one entry dated 2026-09-21 built from the public corpus's published Phase 2 counts (last-30-days: 256 records, all six-digit, highest 100789, TLE 404; analyst: 565 CSV vs 219 TLE, 346 six-digit; Starlink SupGP: 27 nine-digit ids). It is marked `kind: seed`, drawn in amber on the charts, and states that no request was made by this site for it. The total record count of the Starlink SupGP file at the snapshot was not published by the corpus and is left null.

**S-009 — Weekly drift check semantics.** Match/drift/error per source, from the SHA-256 in the corpus manifest (v0.1.0, commit fdf4043). Two stable sources are 16-byte 404 bodies (`No GP data found` for a six-digit object's gp-first TLE); a match there confirms the 404 semantics, and a 200 there would be reported as drift, which is the right alarm.

**S-010 — Library job runs against the latest PyPI releases, in CI's own environment.** `pip install --upgrade sgp4 skyfield` then the reproducers; recorded: versions, whether python-sgp4's C++ extension is active (the classification result on the TLE path depends on it), Python version. Skyfield's timescale uses its bundled data so the job makes no network request of its own. Inputs are annex G values and the vendored vectors (SHA-256 in `data/vectors/PROVENANCE.md`).

**S-011 — Licence and attribution.** MIT, copyright NEOGY LLC, as the corpus. Maintainer named as Honorius Neogy. The site states on every page that it was built with AI assistance under human direction and links to the explanation.

**S-012 — Not done until the owner says so.** No GitHub repository, no Cloudflare configuration, no push, no DNS. The site repository link on the tracker and library pages is given as a path (`jobs/tracker.py`) rather than a URL until the repository exists.

**S-013 — Local runs on 2026-09-21 (owner's instruction: run both jobs once, then stop).** Tracker: 9 requests, 0 errors, 1.96 MB, 05:51–05:52 UTC; last-30-days CSV 231 records, all six-digit, highest 100789, TLE request 404; analyst CSV 594 records (375 six-digit, 219 below 100000) and TLE 219 records, relation holds; Starlink SupGP CSV 11,141 records with 27 nine-digit ids present; drift rotation took the four never-checked `gp-first.php?CATNR=100000` sources, all match (including the 16-byte 404 body). Raw bodies went to a git-ignored local cache, were used once for a leak check (2,318 distinctive values from the bodies searched across every JSON, HTML and JS output: none found) and then deleted. Library job in a throwaway environment with the latest PyPI releases, python-sgp4 2.27 (accelerated build) and Skyfield 1.55: 3 pass, 6 fail, matching the corpus's findings; the classification-through-`twoline2rv` row passes on the accelerated build, as expected. The history therefore starts with two entries for 2026-09-21, the corpus seed and this run; the scheduled job replaces same-day scheduled entries only, never the seed. Nothing was pushed or deployed; no repository or Cloudflare configuration was created.

**S-014 — Activity section: a Pages Function with a two-tier edge cache, static attributions, hand-maintained timeline.** `/api/activity` (`functions/api/activity.js`) makes seven GitHub REST calls per refresh (issues #169 and #171, PRs #170 and #172, the corpus's latest release, the corpus and site repositories) and keeps only state, dates, counts and links: no titles, bodies or comment text enter the output, which a node test asserts with a fake GitHub. Cache: Cloudflare's Cache API with a one-hour "fresh" entry and a 30-day "last good" entry; a GitHub failure serves the last good copy with its original timestamp, `stale: true` and the reason; with no copy at all the function answers 503 and the page keeps its static links. The Cache API is per edge location, so "one refresh per hour" holds per location, not globally; documented in the README, and a KV binding could make it global later if wanted. Authentication: `env.GITHUB_TOKEN` (Pages secret, read-only public-repositories fine-grained token); the function works unauthenticated too. The four attributions are fixed strings in the template, tested for exact single occurrence; the topic lines are the site's own neutral wording, not upstream titles. The timeline is `data/timeline.json`, hand-maintained, seeded with six recorded milestones, each linking to a public record, with public timestamps where they exist (release, issue, PR). Both reading levels: Simple sentences per item are chosen from the live state (open issue, open/draft/merged/closed pull request).

Two hygiene edits first: the workflows' made-up bot addresses replaced by GitHub's noreply identity, and a token-prefixed fake in the node test replaced by a plain string.
