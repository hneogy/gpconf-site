Library status

Two popular free libraries do most of the orbit maths in open-source satellite software. Every week we install their newest versions and check, without touching the network, whether the problems the test kit found are fixed yet.

A weekly job installs the latest PyPI sgp4 and skyfield, runs the corpus’s no-network reproducers (nine-digit id, empty OBJECT_ID, classification) built on the CCSDS 502.0-B-3 annex G example values, and runs the Alpha-5 vectors from corpus v{{ corpus.version }}. Pass means the behaviour the corpus expects; fail means the finding still stands.

If you use python-sgp4 or Skyfield. Three rows in this table will bite you today: nine-digit placeholder numbers in the week after a Starlink launch make the library refuse the record; objects with no launch designation crash its XML reader; and the classification field is overwritten with “U” on the way in. Until the fixes land, read the CSV or JSON formats rather than XML, skip records whose number has nine digits, and do not rely on the classification field. Do this now: follow the test kit’s quick start (clone, fetch, run) with its built-in python-sgp4 adapter; it tells you which of the seventeen cases your installed version survives.

If you use python-sgp4 or Skyfield. Until a release carries PR #172 (merged 2026-09-24, in master, not in 2.27), sgp4.omm.parse_xml followed by initialize raises on an empty <OBJECT_ID/>: read CSV or JSON, where the same records load. Nine-digit SupGP ids raise ValueError in initialize and in EarthSatellite.from_omm (issue #169; PR #170 adds tests only): filter NORAD_CAT_ID >= 100000000 before loading, or leave the launch-week SupGP files aside. initialize resets classification to U, as does the pure-Python twoline2rv: keep the source value yourself if you need it. Do this now: git clone {{ corpus.repo }}.git && cd gp-omm-conformance && python3 tools/fetch.py && python3 -m gpconf run --adapter tests.adapters.sgp4_adapter:Parser. On 2.27 it fails 7 of 17 cases; the count is the thing to watch as fixes land.

What the rows mean

  • Nine-digit id: can the library load a record whose catalog number has nine digits, as CelesTrak publishes for new Starlink launches? Today it refuses.
  • Empty OBJECT_ID: can it read an XML record for an object with no launch designation? Today’s release, 2.27, crashes (our report #171; our fix, PR #172, was merged on 24 September 2026 and reaches users with the next release).
  • Classification C: does it keep the “C” marker on operator-supplied records? Today it changes it to “U” in some paths.
  • Alpha-5 vectors: does it turn numbers into lettered fields and back exactly as the rules say, and refuse the forbidden letters? It encodes and decodes correctly but accepts letters it should refuse.

Method

  • Inputs: the annex G example (GOES 9) with NORAD_CAT_ID replaced by 799501621, or CLASSIFICATION_TYPE set to C, or rendered as a TLE with C; the same values in CelesTrak’s <ndm>-wrapped XML shape with an empty <OBJECT_ID>; the vendored vectors/alpha5.json (SHA-256 recorded in the repository).
  • No provider data, no network: Skyfield’s timescale is loaded from its bundled data. Recorded per behaviour: pass/fail, exception type and message (never element values), the expected behaviour and upstream links; per run: package versions, whether the C++ extension is active, Python version.
  • The classification result on the TLE path depends on the build: the corpus found the pure-Python twoline2rv resets C to U while the accelerated build keeps it; the row above says which build ran.
  • Data: latest.json, history.json. Job source: jobs/library_status.py in the site repository.

Run once against the corpus

Eight more pieces of satellite software were run against all seventeen cases by hand in September 2026, each at one pinned version, and every finding was reproduced by running that software’s own code before it was reported. A count is a result against that version on that date, not a verdict on the project, and it does not say how much a user is affected: some data feeds never carry the input that triggers the failure. The counts do not rank the libraries: one that reads fewer formats has fewer cases it can fail, and the skips are in the technical breakdown.

The last column asks one practical question: can the software load this month’s launches, the 256 objects CelesTrak listed on 21 September 2026, every one numbered above 99,999? Six of the eight read only the TLE format, and CelesTrak leaves every such object out of its TLE feed, so their users are not affected today: the new satellites are simply absent, not misnumbered. Those parsers would misnumber or drop them only if a lettered line reached them from Space-Track or a hand-kept file. Two load them through CelesTrak’s CSV format, and two read the lettered lines correctly.

Hand-run (site/content/library-runs.json): corpus v{{ library_runs.corpus_version }}, runner gpconf {{ library_runs.corpus_version }}, one run per library on the date shown, through a harness or adapter of the corpus’s own over the library’s unmodified parser; recorded in the corpus decision log (D-128 and D-132 to D-141), the specifics in the linked reports. A row is a result for the version named at that date; skip means the library has no reader for the case’s format, not exercised is the runner’s data check. Every finding was reproduced on the library’s own code before it was reported. Rows are added as reports are filed, never before. The gate column is the corpus’s gate over this month’s launches (D-142), read from the record counts each run recorded: per format the parser reads, records are loaded (returned with the expected integer id), misidentified (returned as 0, NaN, a string or a wrong number) or dropped (no record came back); CelesTrak’s TLE request for the group answers HTTP 404, so a TLE-only parser on that feed has nothing to load, and the Alpha-5 rendering stands for what Space-Track’s TLE output carries. Six of the eight read TLE only; the wording names the behaviour and never grades the project. Refused and dropped are not distinguished for these eight runs: they were recorded before the runner’s refusal channel (corpus D-144), so a “dropped” count here may include records the library refused with an error; runs made with the channel report the two apart.
